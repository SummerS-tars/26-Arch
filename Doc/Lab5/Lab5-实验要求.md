## 一、实验目标

在 Lab 4 CSR 基础上，完成 **特权级切换**、**异常陷入（ECALL）** 与 **Sv39 页表 MMU**，使 CPU 能从 M 模式进入 U 模式运行用户程序，并在 U/S 模式下通过虚拟地址访问内存。

## 二、需要实现的指令

| 指令 | 说明 |
|------|------|
| MRET | 从 M 模式 trap 返回；可降低特权级（如 M→U） |
| ECALL | 手动触发环境调用异常，用于特权级升高 |

> **WARNING**：设计 `ECALL` 时请一并考虑 **Lab 6** 的中断与异常处理流程，避免后续大改。

## 三、特权级别

CPU 需维护**当前特权级别**寄存器，并按 RISC-V 规范编码后连接到 **Difftest**。

| 要求 | 说明 |
|------|------|
| 涉及模式 | 本次实验仅涉及 **U** 与 **M** 模式 |
| 上电状态 | CPU 上电时应处于 **M 模式** |
| Bonus | 支持 **S 模式** |

### 特权级别降低（MRET）

CPU 需从 M 模式进入 U 模式以运行用户程序，一般通过 `mret` 完成。注意：`mret` **可以但不一定**导致 M→U。

规范参考：RISC-V 手册 **3.3.2**、**3.1.6.1**。

执行 `mret` 时，CPU 至少应完成：

| 动作 | 说明 |
|------|------|
| 跳转 | 跳转到 `MEPC`，**冲刷流水线** |
| 特权级 | 设置为 `MPP` 中的值 |
| CSR 更新 | `MPIE ← 1`；`MIE ← MPIE`（原值）；`MPP ← 0` |

> **背景**：`mret` 字面意为“从 trap 返回”。用户程序运行中发生中断/异常会提升特权级；处理完毕后 OS 通过 `mret` **返回**用户态继续执行。

### 特权级别升高（ECALL / 异常）

特权级升高由中断、异常引起；本 Lab 中 **`ECALL` 相当于手动触发异常**。

处理异常（含 `ECALL`）时，CPU 至少应完成：

| 动作 | 说明 |
|------|------|
| 跳转 | 跳转到 `MTVEC`，**冲刷流水线** |
| 特权级 | 设置为 **M** |
| 保存 PC | 当前 PC 写入 `MEPC` |
| `MCAUSE` | 按规范表格填写；本 Lab 为 **8** 或 **11**（见下表） |
| CSR 更新 | `MPIE ← MIE`（原值）；`MIE ← 0`；`MPP ←` 执行前的当前特权级 |

**`MCAUSE` 取值（本 Lab）**：

| 值 | 含义 |
|----|------|
| 8 | Environment call from U-mode |
| 11 | Environment call from M-mode |

## 四、MMU（Sv39 页表）

MMU（Memory Management Unit）在 CPU 与内存之间完成**虚拟地址 → 物理地址**翻译。

### 启用条件

| 条件 | MMU |
|------|-----|
| 处于 **M 模式** | **不启用** |
| `satp.mode == 0`（Bare） | **不启用** |
| 处于 **S/U 模式** 且 `satp.mode == 8`（Sv39） | **启用**翻译 |

### satp 寄存器布局

```
63       60 59                  44 43                                0
---------------------------------------------------------------------
|   MODE   |         ASID         |                PPN               |
---------------------------------------------------------------------
```

| 字段 | 位域 | 说明 |
|------|------|------|
| MODE | [63:60] | 分页模式；本 Lab 仅使用 **0**（Bare）或 **8**（Sv39） |
| ASID | [59:44] | 地址空间 ID；**全置 0** 即可 |
| PPN | [43:0] | 根物理页号 = 根页表物理地址 **右移 12 位** |

**MODE 取值（节选）**：

| Value | Name | Description |
|-------|------|-------------|
| 0 | Bare | 无翻译与保护 |
| 8 | Sv39 | 39 位虚拟地址分页（**本 Lab 使用**） |
| 9–11 | Sv48/Sv57/Sv64 | 更高位宽分页（不要求） |

### 页表遍历流程

建议用**状态机**实现三级页表 walk：

1. **第一级**页表基址：`{satp.ppn, 12'b0}`
2. **其余级**页表基址：由上一级页表项 PPN 得到 `{data[53:10], 12'b0}`
3. **索引**：虚拟地址 `[38:30]`、`[29:21]`、`[20:12]` 分别为三级索引
4. **页表项地址**：`页表基址 + 索引 × 8`（每项 8 字节）
5. **最终物理地址**：`{data[53:10], vaddr[11:0]}`

> fetch 与 memory 的内存访问**均需经 MMU 翻译**。MMU 需读完整 **64 位**页表项，**不要用 ibus** 做地址翻译；应使用**单一 MMU** 统一翻译指令与数据地址。

### 总线改造（二选一）

当前典型拓扑：

```
ibus -> i_cbus -> | CBus    | -> CBus -> 内存
dbus -> d_cbus -> | Arbiter |
```

#### 方式 1：弃用 ibus，MMU 接在 dbus 上

```
ibus (deprecated)  --------------------------------------------------> | CBus    | -> CBus -> 内存
your_dbus_to_fetch -> | Your DBus    | -> dbus -> | MMU | -> d_cbus -> | Arbiter |
your_dbus_to_mem   -> | Arbiter      |
```

- 自写 Arbiter，将 1 条 dbus 分给 fetch 与 memory（可参考 `CBusArbiter.sv`）
- MMU 写在原 dbus 路径上

#### 方式 2：MMU 接在仲裁后的 CBus 上

```
ibus -> i_cbus -> | CBus    | -> CBus -> | MMU | -> 内存
dbus -> d_cbus -> | Arbiter |
```

- MMU 需知晓 **当前特权级**、**SATP**
- 因 `Core` 与 `CBusArbiter` 同级，须在 **SimTop / VTop** 将上述信号绕行
