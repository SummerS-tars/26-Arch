### 二、 Lab 4 阶段化执行规划
为了确保进度可控且无遗漏，开发过程将拆分为 5 个 Phase，每个阶段必须满足相应的验收条件（Acceptance Criteria, AC）才能进入下一阶段。

#### Phase 0: 需求对齐与工程初始化

- **目标**：彻底解构 Lab 4 原始实验指导书，建立工程基础，杜绝需求误解。
- **执行动作**：
  1. 在 `Doc/Lab4/` 下创建 `Requirements_Lab-4.md`，逐字逐句拆解实验要求。
  2. 在 `.cursor/plans/` 下创建 `lab4.plan.md` 和配套的 `PlanFix.md`。
  3. 建立需求追溯矩阵（Requirement Traceability Matrix），将每个得分点映射到对应的硬件模块。
- **验收条件（AC）**：
  - [ ] 原始需求文档中的所有粗体/强调字句均已转化为具体的 TODO list。
  - [ ] 确认 `ready-to-run/lab4/` 目录下的 `lab4-test.S` 覆盖了哪些新增指令。

#### Phase 1: 数据通路与控制逻辑设计（架构蓝图）

- **目标**：在不写一行 Verilog/Chisel 代码的情况下，完成逻辑图的更新。
- **执行动作**：
  1. 针对新增指令（如 CSR 操作或中断指令），设计译码逻辑（Decode Logic）。
  2. 规划流水线刷新（Flush）与暂停（Stall）的新触发条件。
  3. 绘制包含新增模块（如 CSR File, Exception Controller）的 5 级流水线数据通路图。
- **验收条件（AC）**：
  - [ ] 完成 `Doc/Lab4/Architecture_Design.md` 编写。
  - [ ] 梳理出所有新增的控制信号及其在不同指令下的真值表。

#### Phase 2: 核心模块独立开发与单元测试

- **目标**：实现 Lab 4 引入的核心新组件（如 CSR 寄存器堆、异常判断模块），并确保其独立工作正常。
- **执行动作**：
  1. 编写新增模块的 RTL 代码。
  2. 为这些独立模块编写简易的 Testbench，验证基本的读写与状态转移。
- **验收条件（AC）**：
  - [ ] 新增模块代码通过编译，无语法错误。
  - [ ] 独立模块的波形图符合预期。

#### Phase 3: 流水线集成与数据冒险/控制冒险适配

- **目标**：将新模块接入 CPU 骨架，并处理引入的新冒险（Hazards）。
- **执行动作**：
  1. 将 CSR 和异常控制模块接入现有的流水线阶段（通常在 EXE 或 WB 阶段）。
  2. 修改前递（Forwarding）单元，支持 CSR 到 ALU 的数据前递。
  3. 修改 Hazard Detection Unit，支持异常发生时的全局流水线冲刷。
- **验收条件（AC）**：
  - [ ] CPU 顶层模块例化成功。
  - [ ] 能够正确执行前几个 Lab 的基础测试（回归测试，确保新代码未破坏原有功能）。

#### Phase 4: 汇编级验证与文档交付

- **目标**：使用官方测试文件进行全覆盖测试，输出最终交付物。
- **执行动作**：
  1. 加载 `ready-to-run/lab4/lab4-test.bin` 进行仿真运行。
  2. 对比每条指令执行后的寄存器状态与预期结果。
  3. 如果出现错误，在 `PlanFix.md` 中记录 Bug 现象、排查思路与修复方案。
  4. 整理最终的实验报告。
- **验收条件（AC）**：
  - [ ] `lab4-test.S` 全部测试点通过，生成完整的 `success_output.txt` 日志。
  - [ ] 捕获关键波形图或串口输出截图作为验证凭证。
  - [ ] 完成 `Doc/Lab4/report.md`，内容包含架构图、冒险处理逻辑、测试结果与复盘。

### 三、 确保“无遗漏、误解”的防线策略
为保障对原始要求的绝对还原，建议在整个开发周期内采取以下两项约束：

1. **指令集白皮书锚定**：针对 Lab 4 要求支持的每一条新指令，直接查阅官方的指令集手册（如 RISC-V Unprivileged & Privileged Spec），将手册中的伪代码逐行翻译为硬件控制逻辑，不凭经验猜测。
2. **双向追溯测试**：在 Phase 0 提取出需求列表后，在 Phase 4 必须为每一个需求点找到一条对应的汇编测试代码。如果 `lab4-test.S` 没有覆盖某个需求，需手动编写 `lab4-extra-test.S` 以补全测试闭环。
